## Full learner journeys
1. First launch without credentials/network: Home -> track -> first lesson -> valid practice feedback -> summary; there must be no AI setup gate.
2. Wrong answer -> authored clue -> correct retry -> fresh check -> save failure -> recovery/temporary session -> restart -> mistake review. Check dominant message and next action at every step; save status persists separately from grading feedback.
3. Fresh question issuance -> hint admission -> forced crash -> restart -> correct retry: never claim independent first-attempt success.
4. Start AI -> edit answer -> leave lesson -> reset -> deliver old response: no stale hint, no old save bytes and no destroyed-worker memory access.
5. Two walkthroughs and three comparisons use real longest authored records with keyboard navigation, narrow window and enlarged text; examples remain language-labelled and no required control clips.
6. Failed primary and backup: original files preserved; temporary practice works; new fresh assessment waits for durable issuance; reset is explicit and accurately reports failure/success.

## State coverage
Screen routes: Home, track chooser, catalogue, lesson, Progress, review list, Settings. Each gets loading if asynchronous, empty, error, success and partial states per plan matrix. Hint states: Idle -> Loading -> Ready/Failed/Cancelled with source and context. Save states: Clean -> Dirty -> Saving -> Saved/Failed; generation mismatch cannot apply success. Walkthrough states: unavailable or bounded valid index; Previous at zero and Next at end are disabled or no-op consistently.

## Chaos and determinism
Use injectable filesystem operations, an explicit save-writer barrier, fake transport and controllable time. Do not use random failure timing or real sleeps as correctness assertions. Force stop/interruption only of the test-owned isolated process in a dedicated test data directory; do not touch real learner saves or terminate unrelated processes. Simulate short writes, denied read, full storage, unsupported version, stale callbacks and out-of-order completion. A failed simulated case must report its exact expected and actual state.

## Performance and platform checks
Measure navigation frame time, content load, save latency and shutdown on named OS/CPU/hardware. Proposed 60 FPS is a target, not a passed claim. Test caps at and above limits and ensure clear refusal rather than unbounded growth. Test the selected minimum macOS version/architecture before advertising it. VoiceOver/text editing feasibility requires a separate early prototype; keyboard-only success is not a screen-reader pass.

## Acceptance and limitations
Every test family above must have recorded evidence or an explicitly approved limitation. There are no current test results, code coverage measures, eval baselines or runtime metrics. Unit tests cannot establish pedagogy, screenshot review cannot prove accessibility, and the six-exercise evaluation cannot guarantee every AI output. A local academic build is not a public signed/notarised distribution claim.

## Exact recovery and shutdown oracles added by independent review
- T04/T06: restore a backup predating a wrong answer/help event. Unresolved same-revision evidence must show unverified recovery provenance and cannot become independent-first. Previously committed completed immutable facts in the backup remain as recorded.
- T08: reset -> acknowledge -> corrupt new primary -> restart. Restore only a compatible backup from the selected generation; never pre-reset progress. Corrupt manifest with existing generation files enters temporary/recovery mode.
- T07/T08: interrupt before temp creation, during bytes, after validated closed temp, before/after replacement, before/after manifest switch and before/after acknowledgement. Assert authority old before manifest switch and new after, no duplicate event, no false Saved/Reset complete.
- T03/T04: duplicate Submit while first commit is pending; admitted help with failed commit; help in temporary mode followed by recovery. No pristine independence is manufactured.
- T15: close during DNS/connect/TLS/upload/read, cancellation and full mailbox publication; then verify ordered writer outcome, joined worker and no stale state mutation.
- Resource fixtures combine maximum lesson/exercise/visual counts and long IDs; the serialized aggregate profile must fit its cap. Test aggregate cap and cap+1, not just per-record limits.
